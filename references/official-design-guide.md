整理日期：2026-10-26

> 本文件按官方页面章节忠实整理，供开发/审查时对齐官方口径。原文配图（颜色板、按钮样式、机型示意）无法以文本呈现，凡涉及图片的数值均单独标注来源。

## 0. 总纲

基于微信小程序轻快的特点，官方拟定小程序界面设计指南和建议。设计指南建立在**充分尊重用户知情权与操作权**的基础之上，旨在微信生态内建立**友好、高效、一致**的用户体验，同时最大程度适应和支持不同需求。

七大章节：友好礼貌、清晰明确、便捷优雅、统一稳定、视觉规范、设计稿标准尺寸、资源下载。

---

## 一、友好礼貌

减少无关设计元素对用户目标的干扰，礼貌展示服务，友好引导操作。

### 1.1 重点突出

每个页面都应有一个明确的重点，用户进入新页面能快速理解页面内容。确定重点后，应尽量避免出现与用户决策和操作无关的干扰因素。

### 1.2 流程明确

用户进行某一个操作流程时，应避免出现目标流程之外的内容打断用户。

---

## 二、清晰明确

清晰告知用户"身在何处、可以往何处去"，确保在页面中穿梭不迷路。

### 2.1 导航明确，来去自如

- 小程序**不提供统一导航栏样式**，开发者需自行设计首页与次级页面导航。
- 所有次级页面**左上角提供返回上一级操作**。
- iOS 用户可通过界面边缘向右滑动返回；Android 用户通过物理返回键返回。

**小程序菜单（胶囊）**

- 所有页面（含内嵌网页和插件）右上角都有微信官方控件，**开发者不可自定义其内容**。
- 只能选择**深、浅两套基础配色**以适应页面风格。
- 菜单固定在界面固定位置，**设计时必须预留该区域空间**；在其附近放置可交互元素要特别注意交互冲突与易用性。

**页面内导航**

- 可添加自有导航，须保持不同页面间导航一致、指向清晰、有路可退。
- 受手机屏幕尺寸限制，导航应尽量简单。
- 建议自有导航样式与官方控件保持一定差异，便于区分。

**标签分页（Tab）导航**

- 可固定在页面顶部或底部，便于分页切换。
- 数量**不得少于 2 个，最多不超过 5 个**；为确保点击区域，**建议不超过 4 项**。
- 一个页面**不应出现一组以上**的标签分页栏。
- 首页可使用微信原生底部标签分页样式（仅首页可用），可自定义图标、文案、文案颜色等；图标尺寸等参考开发文档和 WeUI 基础控件库。
- 顶部标签分页栏颜色可自定义，但必须保持**可用性、可视性、可操作性**。

### 2.2 减少等待，反馈及时

**启动页加载**：突出展示品牌特征与加载状态。除品牌 Logo 外，其余元素（如加载进度指示）由微信统一提供，不可更改，无需开发。

**页面下拉刷新加载**：微信提供标准能力和样式，开发者无需自行开发。

**页面内加载反馈**：自定义加载样式应尽可能简洁，用简单动画告知加载过程。

**模态加载**：覆盖整个页面，无法明确告知加载位置/内容，易引起焦虑，**谨慎使用**；除全局性操作外不要使用。

**局部加载反馈**：只在触发加载的页面局部反馈，更有针对性、页面跳动小，**官方推荐**。

**全局加载反馈**：可参考官方样式，使用标题栏提示加载过程。

**加载反馈注意事项**

- 载入时间较长时，应提供**取消操作**，并用**进度条**显示载入进度。
- 载入过程中**保持动画效果**；无动画的加载容易让人误以为界面卡死。
- **同一页面不要同时使用超过 1 个加载动画**。

**结果反馈**

- 页面局部操作 → 在操作区域**直接反馈**（如多选控件点击前后状态）。
- 页面级操作结果 → 弹出式提示、模态对话框或结果页。

| 反馈形式 | 适用场景 | 关键约束 |
|---------|---------|---------|
| 图标型弹出提示 | 轻量级成功提示，不需强调 | **1.5 秒自动消失**；**不适用于错误提示**（一闪而过无法明确告知） |
| 文字型弹出提示 | 轻量解释当前状态、不严重的错误 | 1.5 秒自动消失，不打断流程 |
| 模态对话框 | 需用户明确知晓的结果，可附下一步指引 | 打断流程，用于重要结果 |
| 结果页 | 操作已是当前流程终结 | 最强烈明确，可给下一步指引 |

### 2.3 异常可控，有路可退

- 异常场景是用户最沮丧、最需要帮助的时候，必须**格外注意异常状态设计**。
- 出现异常时给出**必要状态提示 + 解决方案**，让用户有路可退。
- **杜绝**异常状态下用户莫名其妙又无处可去、停滞在某一页面。
- 表单页（尤其表单项较多）应**明确指出出错项**，便于修改。

**表单出错三种形态**

| 类型 | 用法 |
|------|------|
| 原位报错 | 在出错字段处直接提示，适合单字段校验 |
| 公告报错 | 表单顶部告知错误原因，并标识出错字段 |
| 模态报错 | 强提示，适合需阻断的严重错误 |

选择依据：错误优先级、严重程度、校验时机。

## 三、便捷优雅

手指操作精度远不如键鼠，需充分利用手机特性，让用户便捷优雅地操控界面。

### 3.1 减少输入

- 利用现有接口减少输入（如摄像头识别银行卡、地理位置接口等），提高效率与准确性。
- 不得不手动输入时，**尽量让用户做选择而非键盘输入**：回忆易于记忆，有限选项中选择比纯记忆输入更容易，且能减少密集键盘的输入错误。
- 示例：搜索时提供**搜索历史快捷选项**，减少或避免不必要的键盘输入。

### 3.2 避免误操作

- 手指点击精度低，设计可点击控件时须充分考虑**热区面积**，避免可点击区域过小或过于密集。
- PC 界面不做适配直接移植到手机，最容易出现此类问题。
- 手机分辨率各不相同，但换算成物理尺寸后，**最适宜点击尺寸大致在 7mm - 9mm 之间**。
- 微信标准组件库中的控件已考虑点击效果与不同屏幕适配，**推荐使用或模仿标准控件尺寸**设计。

### 3.3 利用接口提升性能

- 微信设计中心提供网页标准控件库：[Sketch 设计控件库](https://wximg.gtimg.com/shake_tv/mina/WEUI_1_0_161226_Sketch.zip)、[Photoshop 设计控件库](https://wximg.gtimg.com/shake_tv/mina/WeUI1.0.psd.zip)。
- 控件已充分考虑移动端特点，保证可用性与操作性能。
- 微信团队持续完善小程序接口与公共库，利用这些资源可提升服务速度与页面性能。

---

## 四、统一稳定

- 不同页面间保持**统一性与延续性**，尽量使用**一致的控件和交互方式**。
- 统一的页面体验和延续性元素能帮助用户以最少学习成本达成目标，减轻页面跳动的不适感。
- 可按需使用微信提供的**标准控件**，达到统一稳定的目的。

## 五、视觉规范

### 5.1 字体

- 微信内字体使用**与所运行的系统字体保持一致**（不指定自定义字体）。
- 常用字号：**22、17、15、14、12 (pt)**。

**pt → rpx 换算**（iPhone 6 基准：375pt = 750rpx，1pt = 2rpx）

| 字号 (pt) | 对应 rpx | 典型用途 |
|-----------|---------|---------|
| 22 | 44rpx | 大标题 / 金额数字 |
| 17 | 34rpx | 页面标题、导航栏标题 |
| 15 | 30rpx | 小标题、强调正文 |
| 14 | 28rpx | 正文 |
| 12 | 24rpx | 辅助说明、标签（最小可读字号） |

> 与本 skill 红线"字体最小 24rpx"一致：12pt = 24rpx 即下限。

### 5.2 色板

官方色板以图片形式给出（文字用色、彩色色板），页面未提供十六进制数值。落地时以 WeUI 标准色为准：

| 用途 | WeUI 标准值 |
|------|------------|
| 主文字 | `#000000`（或 `#1A1A1A`） |
| 次要文字 | `#888888` |
| 辅助/禁用文字 | `#B2B2B2` |
| 分割线 | `#E5E5E5` |
| 页面背景 | `#F7F7F7` |
| 品牌绿（主操作） | `#07C160` |
| 警告红 | `#FA5151` |
| 链接蓝 | `#576B95` |

> 上表为 WeUI 官方控件库通用值，非本次页面文本直接给出，作落地参考。

### 5.3 列表

官方以图示规范列表的行高、缩进、分割线、左右信息对齐。落地要点：统一行高、分割线用 `#E5E5E5`、左右留白一致、可点击整行反馈。

### 5.4 表单

官方以图示规范表单的标签、输入区、报错态。落地要点：标签与输入对齐、必填标识清晰、错误态原位提示、控件高度符合 7-9mm 触控标准。

### 5.5 按钮

官方以图示规范主/次按钮、禁用态、尺寸。`button` 组件属性（来自官方组件文档）：

| 属性 | 取值 | 默认 | 说明 |
|------|------|------|------|
| `size` | `default` / `mini` | default | 按钮尺寸 |
| `type` | `primary`（绿）/ `default`（白）/ `warn`（红） | default | 样式类型 |
| `plain` | boolean | false | 镂空，背景透明 |
| `disabled` | boolean | false | 禁用 |
| `loading` | boolean | false | 名称前带 loading 图标 |
| `hover-class` | string | `button-hover` | 按下样式；默认 `{background-color: rgba(0,0,0,0.1); opacity: 0.7}` |
| `hover-start-time` | number | 20 | 按住多久出现点击态（ms） |
| `hover-stay-time` | number | 70 | 松手后点击态保留（ms） |

落地要点：主按钮用 `type="primary"`（品牌绿 `#07C160`）；一个页面只保留一个主按钮；圆角与高度统一；禁用态用 `disabled` 而非仅改颜色；触控区不小于标准控件。

### 5.6 图标

官方以图示规范图标风格、尺寸、与文字对齐。落地要点：线性/面性风格统一、图标尺寸随字号等比、可点击图标加足热区。

## 六、设计稿标准尺寸

官方给出两种基准宽度方案，**二选一**：

### 6.1 采用 375px 基准宽度

- 页面遵循**固定布局**，不同机型采取**放大缩小**的布局规则。
- 对应 rpx：设计稿 375px 宽 → 1px = 2rpx。

### 6.2 采用 390px 基准宽度

- 页面遵循**响应式布局**，不同尺寸机型**需要适配调整**。
- 适合需要在大屏/折叠屏保持信息密度的产品。

> 选择建议：内容型、工具型小程序用 375px 固定布局更省事；需要 iPad/折叠屏/横屏体验的用 390px 响应式布局，并配合本 skill 范式三的 max-width + 断点。
